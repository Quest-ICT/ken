# Batch 2 — audit result

## 1. The headline

**Yes, but not in COMM's shape.** COMM's seams were two live mechanisms competing (endpoint rowid vs party key, channel vs scope). Stations have almost none of that: the station code is internally consistent, and the party-model damage stops at the COMM boundary. What stations have instead is **one-sidedness** — a write path with no read path, an agent surface with no human surface, a store function with no caller — plus **a large body of prose that describes controls nobody can reach**. Thirty-two items below; roughly a third are operator- or agent-facing text that is false *today*, and those are the ones to do first, because they are the class that already put "off by default" on the public website.

The single worst finding is not in stations at all: `kb_record_outcome` writes a table with **no reader anywhere**, and every session is told at connect to call it after every entry.
